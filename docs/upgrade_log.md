# 업그레이드 이력

## 2026-09-20 — 전체 점검에서 나온 버그 일괄 수정

전 모듈 정적 점검(12,158줄)에서 나온 결함을 고쳤다. 실행 검증은 CI(compileall +
import 스모크)와 실제 사용으로 확인해야 한다.

### 데이터 소실 (치명)

- **랩 프로필 초기화/삭제/이름변경이 PAPER 계좌 기록을 전멸시키던 버그**
  (`lab.py: reset`). `PaperBroker.reset()`에 mode를 안 넘겨 기본값 `"PAPER"`의
  trades/orders/signals/equity가 통째로 지워졌다. `mode=lab_mode(name)` 명시.
- **equity 테이블 PK를 `ts` 단독 → `(mode, ts)` 복합키로** (`storage.py`).
  운용랩처럼 여러 모드가 같은 초에 기록하면 INSERT OR REPLACE가 서로를 덮어써
  자산곡선·MDD·성과비교가 표본 유실 상태로 계산됐다. 기존 DB는 시작 시 자동
  마이그레이션된다.
- **부분체결 매도를 전량 청산으로 기록하던 버그** (`storage.py: close_trade`,
  `trader.py: _close`). 체결분만 닫고 잔량은 미결 거래로 남겨 손절/트레일링
  관리를 계속 받는다.

### 조용히 죽어 있던 기능

- **장 마감 후 처리(일봉/분봉 수집 + AI 리뷰)가 평일에 한 번도 안 돌던 버그**
  (`trader.py: tick`). 거래일 16시의 세션이 `"after"`인데 장외 분기가
  `"closed"/"pre_auction"`만 받았다. 덤으로 15:30 이후 강제청산 주문을
  반복 시도하던 것도 함께 사라진다.
- **Gemini 기본 모델명이 실존하지 않는 `gemini-3.5-flash`** → `gemini-2.5-flash`.
  AI 리뷰/제안/거부권이 전부 무음 실패 상태였다. 설정 파일에 남은 옛 값도
  로드 시 자동 교정.
- **AI 거부권 프롬프트에 상하한가/시장경보/거래정지가 None으로 들어가던 버그**
  (`trader.py: _enter`). 막으라고 지시한 근거 4개를 실제로 채워서 넘긴다.
- **업종 집중도 관문이 종목DB를 안 받으면 무력화되던 버그**
  (`storage.py: set_sector`). UPDATE → 업서트로 바꿔 마스터 없이도 sector가 남는다.

### 백테스트 ↔ 실거래 정합

- **"당일 종가 청산" 전략(변동성 돌파)이 백테스트에선 다음날 종가에 나가던 버그**
  (`backtest.py`). 진입 봉에서 손절 우선(최악 가정) → 익절 → 종가청산을 본다.
  **기존 백테스트 수치(README 성과표 포함)는 이 수정 전 기준이므로 다시 돌려야 한다.**
- 사이징의 최소주문금액 보정 규칙을 실거래(`risk.position_size`)와 동일하게 통일.
  비용 관문도 종목의 시장 구분(코스피/코스닥 호가단위)을 실거래처럼 반영.

### 배포/기타

- `release.py --local`이 커밋·태그를 만든 뒤 반드시 실패하던 exe 이름 불일치
  (`KIS자동매매.exe` → build.py와 같은 `Clistock.exe`).
- 자동 업데이트 다운로드가 리다이렉트 최종 호스트를 재검증하지 않던 것 보강.
- `config/settings.json.bak`을 깃 추적에서 제외.
- 조정 매수(dip_buy)를 README 전략표와 전략 자동 탐색에 연결.
- 휴장일 사전조회가 `days` 인자를 무시하고 한 달치만 받던 것 수정.
- GUI: 작업 잠금 경쟁, 워커 스레드의 Tk 위젯 접근, 설정 저장 중 부분 반영 수정.

## 2026-08-21 — 검증 신뢰도 + 거래비용/체결현실성

기존 제안서(`upgrade_suggestions.md`) 7항목 중 3(섹터 분산)·4(슬리피지)·5(텔레그램)는
이미 구현돼 있었다. 실제로 비어 있던 두 축을 채웠다.

### A. 검증 신뢰도 — "이 수익률이 재현되는가"

**1) 워크포워드 검증** (`analysis.py: walk_forward`)

골라야 한다. 그래서 확장형(anchored)으로 구간을 밀며 **앞 구간에서만 고르고,
고를 때 보지 않은 뒤 구간으로만 채점**한다.

**2) 바이앤홀드 벤치마크** (`backtest.py: _buy_hold`)

같은 기간·같은 종목을 동일가중으로 사서 끝까지 들고 있었을 때의 수익률과 MDD를
매 백테스트마다 함께 계산한다. 매수 수수료와 최종 매도 수수료·세금까지 동일하게 뺀다.
지표에 `bh_return_pct` / `bh_mdd_pct` / `alpha_pct`가 추가됐고,
전략이 보유를 못 이기면 결과 경고에 그 사실이 명시된다.

**3) 스캐너 관문에 벤치마크 추가** (`scanner.py: GATES["min_alpha_pp"]`)

기존 5개 관문(표본·비용후수익·손실확률·연도일관성·MDD)에
**"그냥 사서 들고 있는 것보다 나은가"**를 6번째 관문으로 넣었다.
동점이면 탈락한다.

### B. 거래비용 / 체결현실성 — "이 거래를 할 값어치가 있는가"

5년 백테스트에서 전략 대부분은 시장에 진 게 아니라 거래비용에 졌다.
그 손실은 전략을 고쳐서 되찾는 게 아니라 **진입 전에 걸러야** 한다.

**1) 왕복비용 계산** (`risk.py: round_trip_cost_pct`)

    수수료 x 2 + 매도세 + 슬리피지 x 2      (기본값 = 0.38%)

가격을 주면 최소 호가단위(1틱)를 함께 본다. 1틱은 어떤 실력으로도 줄일 수 없는
비용이라, 저가주에서 1틱이 슬리피지 가정보다 크면 그쪽을 쓴다.
(예: 300원 종목 → 0.85%)

**2) 비용 관문** (`RiskConfig.min_edge_cost_ratio`, 기본 3.0배)

기대이익 ÷ 왕복비용 < 3배면 진입을 취소한다.
기대이익은 목표폭, 목표가 없는 추세추종형은 손절폭(1R)을 쓴다.

**3) 유동성 관문** (`RiskConfig.min_turnover_amount`, 기본 5억원)

- 최근 20일 평균 거래대금이 하한 미만이면 차단 — 살 때는 되는데 팔 때 못 빠져나오는 종목
- 1주 가격이 1회 주문상한을 넘으면 차단 — 고가주는 1주도 못 산다는 걸 신호 전에 알려준다

**4) 백테스트에 동일 관문 적용** (`backtest.py: _gate`)

실거래와 같은 식을 쓴다. 백테스트에서만 통과하는 거래가 있으면 그 수익률은
실계좌에서 나오지 않는다. 취소 건수는 `gated_cost` / `gated_liquidity`로 남고
경고에도 표시된다.

**5) 화면 노출**

- 감시 현황에 **비용대비** 컬럼(기대이익이 왕복비용의 몇 배) 추가
- 새 판정 **`GATED` (관문차단)** — 전략은 사자고 했지만 시스템이 막은 상태.
  주황색으로 구분되고 사유가 `watch_eval` DB에도 쌓인다
- 상세 팝업에 왕복비용·배수·차단 사유
- [설정] → 자금관리에 **거래비용 / 체결현실성** 그룹 (0을 넣으면 관문 끔)

### 관문을 끄고 싶을 때

`min_edge_cost_ratio = 0`, `min_turnover_amount = 0`으로 두면 기존과 동일하게 동작한다.
다만 관문을 풀면 거래는 늘고 백테스트 수익률도 올라가는데,
**그 늘어난 거래가 바로 5년 백테스트에서 계좌를 깎았던 거래들**이다.

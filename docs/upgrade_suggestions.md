# AI 주식 자동매매 시스템 (`ai_stock_trader`) 업그레이드 제안 요약서

해당 문서는 현재 시스템의 구조를 기반으로 **안정성을 높이고 수익성을 극대화하기 위해 추가 개발이 필요한 기능**들을 정리한 것입니다. 이 문서를 Claude 등 다른 AI에게 전달하여 즉시 코드 작성 및 모듈 추가 작업에 활용할 수 있습니다.

---

## 1. 외부 뉴스 및 공시 데이터 크롤링을 통한 AI Veto(방패) 기능 강화
현재 AI Veto 기능은 시스템이 주는 단순한 가격/시세 정보에만 의존하고 있습니다.
*   **요구사항:** 네이버 금융 뉴스, DART(전자공시시스템) API 등을 연동하여 해당 종목의 최신 악재(유상증자, 횡령, 하한가 테마 등)를 크롤링하는 모듈(`news_crawler.py`)을 추가.
*   **적용:** 진입(Entry) 신호 발생 시 크롤링한 요약 뉴스를 `ai_advisor.py`의 Veto 프롬프트에 컨텍스트로 제공하여, **명백한 악재 뉴스가 있을 때 AI가 매수를 완벽히 차단**하도록 업그레이드.

## 2. API 통신 모듈의 비동기(Async) 리팩토링
현재 `kis_client.py`는 `requests` 라이브러리를 사용한 동기(Synchronous) 방식으로 구현되어 있습니다. 관심종목이 늘어나면 데이터를 가져오는 과정에서 병목 현상이 발생할 수 있습니다.
*   **요구사항:** `requests` 대신 `httpx` 비동기 클라이언트나 `aiohttp`를 사용하도록 `kis_client.py`를 비동기식(`async/await`)으로 전면 개편.
*   **적용:** 여러 종목의 현재가나 분봉 데이터를 조회할 때 `asyncio.gather`를 통해 병렬로 데이터를 수집하여 틱 지연(Latency)을 최소화.

## 3. 포트폴리오 섹터(테마) 분산 및 상관계수 기반 리스크 관리
현재 `risk.py`는 자산 단위의 손실과 종목 단위의 비중만 관리하고 있습니다. 특정 테마(예: 반도체, 이차전지)가 일제히 하락할 때 리스크에 노출될 수 있습니다.
*   **요구사항:** 보유 종목들의 산업군(섹터)을 분류하거나 종목 간의 가격 상관계수를 계산하는 로직 추가.
*   **적용:** `risk.py`의 진입 관문(`check_entry`)에서 "특정 섹터 비중이 전체 자산의 40%를 초과하면 해당 섹터 종목의 추가 매수를 차단"하는 기능 구현.

## 4. 백테스팅 엔진(`backtest.py`) 현실성 강화 (슬리피지 및 체결 지연)
과거 데이터를 돌려보는 백테스트가 실제 매매와 차이가 나는 가장 큰 이유는 체결 지연과 슬리피지입니다.
*   **요구사항:** 시장가 주문 또는 지정가 돌파 주문 시 발생하는 **슬리피지(Slippage) 페널티**를 세밀하게 모델링하여 `backtest.py`에 적용.
*   **적용:** 백테스트 거래 시 매수는 실제 고가 쪽에 가깝게, 매도는 저가 쪽에 가깝게 체결되는 페널티 비율 변수(`slippage_pct`)를 추가하고 커미션(세금/수수료)과 합산 처리.

## 5. 실시간 외부 메신저 알림 연동 (Telegram / Discord Webhook)
현재 매매 체결 내역이나 킬스위치(Halt) 발동 내역이 로그(로컬)와 자체 GUI에만 남을 가능성이 높습니다.
*   **요구사항:** `notifier.py` 모듈을 신규 생성하여 Telegram Bot API 또는 Discord Webhook 연동 구현.
*   **적용:** `trader.py`의 `emit` 이벤트가 발생할 때, [위험(Risk)], [체결(Trade)], [AI 리뷰] 등의 카테고리별로 필터링하여 사용자 핸드폰으로 즉각 푸시 알림 발송.

## 6. 머신러닝(ML) 기반의 보조 지표 필터 도입
단순 룰 기반(이동평균, 돌파 등) 외에, 머신러닝 예측을 확률 필터로 사용하는 하이브리드 전략.
*   **요구사항:** XGBoost 또는 LightGBM을 사용해 장 마감 시점에 틱 데이터를 학습하여 '다음 날 상승 확률'을 스코어링하는 스크립트 작성.
*   **적용:** `strategies.py`의 진입 로직에서 ML 모델이 계산한 **상승 확률 스코어가 55% 이상일 때만 기존 룰 기반 매수 신호를 승인**하도록 2중 관문 구축.

## 7. 멀티 전략 - 다중 계좌(Multi-Account) 분리 운용 로직
단기 트레이딩용과 장기 스윙용 전략이 하나의 계좌 예수금을 공유하면 포지션 사이즈 조절(Risk Sizing)이 꼬일 수 있습니다.
*   **요구사항:** `settings.py`에서 복수의 계좌(App Key / Secret / 계좌번호)를 배열로 입력받을 수 있도록 구조 변경.
*   **적용:** 전략(Strategy) 객체마다 특정 계좌 번호를 바인딩하여, `TradingEngine`이 전략별로 지정된 계좌의 예수금만 사용하고 주문을 분리해서 전송하도록 설계.

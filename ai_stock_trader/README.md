# KIS 자동매매 시스템

한국투자증권 OpenAPI 기반 자동매매 프로그램. 실행 파일 **하나**로 데이터 수집 → 백테스트 →
모의투자 → (검증 후) 실전까지 이어진다.

**실행: 바탕화면의 `KIS자동매매` 아이콘을 더블클릭.** (검은 cmd 창은 뜨지 않는다)

개발용으로 소스에서 바로 돌리려면:

```
python run.py
```

---

## 설계 원칙

참고한 글이 말하는 순서 그대로다.

```
매매조건 정의 → 코드화 → 백테스트 → 모의계좌 → 극소액 실전
```

여기서 가장 중요한 건 **매매 결정을 AI에게 맡기지 않는 것**이다.

"지금 삼성전자 살까?"를 AI에게 물으면 같은 상황에서도 매번 다른 답이 나온다.
그러면 백테스트가 불가능하고, 백테스트가 불가능하면 그 전략이 돈을 버는지 확인할 방법이 없다.
그건 자동매매가 아니라 자동 도박이다.

그래서 이 시스템에서:

- **방아쇠를 당기는 건** 백테스트된 규칙 (`app/strategies.py`)
- **AI가 하는 일**은 ① 하루 거래 리뷰 ② 백테스트 결과 해석과 파라미터 제안
  ③ 진입 거부권(악재 필터) — 진입을 *막을* 수만 있고 *만들* 수는 없다

## 시작하기

### 1. 설치

```bash
pip install -r requirements.txt
```

### 2. 키 설정

`.env.example`을 `.env`로 복사하고 값을 채운다. 모의투자 키만 있어도 동작한다.

| 키 | 용도 |
|---|---|
| `KIS_MOCK_*` | 모의투자 주문 |
| `KIS_REAL_*` | 시세 조회 (+ REAL 모드에서만 주문) |
| `GEMINI_API_KEY` | AI 리뷰/제안 (없어도 매매는 됨) |

> **실전 키를 시세용으로 쓰는 이유**: 모의투자 도메인은 분봉·휴장일 등 일부 시세 API를
> 지원하지 않는다. 그래서 시세는 실전 도메인, 주문은 모의 도메인으로 분리했다.
> 시세용 클라이언트는 `read_only=True`로 잠겨 있어 **주문 메서드 호출 자체가 예외를 던진다.**

### 3. 점검

```bash
python run.py --check
```

### 4. 작업 순서

GUI의 탭 순서가 곧 작업 순서다.

1. **[종목]** 매매할 종목을 고른다
2. **[데이터]** 일봉 수집 (1250일 = 5년 권장. 200일선 전략은 워밍업만 220봉이라
   400일로는 검증 구간이 8개월밖에 안 남는다)
3. **[백테스트]** 전략 실행 → 지표와 경고 확인
4. **[운용랩]** 장투/스윙/단타를 동시에 가상 운용하며 비교
5. **[리스크]** 안전장치 확인
6. **[대시보드]** 모의투자 시작

## [운용랩] — 내 매매방식을 만들고 비교하기

"장투로 하면 얼마 벌고 단타로 하면 얼마 벌까"를 알려면 **같은 기간, 같은 시세로 동시에**
굴려봐야 한다. 하나씩 순서대로 돌리면 시장 상황이 달라져 비교가 안 된다.

프로필 하나 = 가상계좌 하나다. 예수금을 공유하지 않으므로 포지션 사이징이 섞이지 않는다.

**기본 프리셋 5개**

| 프로필 | 전략 | 1회손실 | 보유 | 청산 |
|---|---|---|---|---|
| **조정 매수(추천)** | 조정 매수 (52주 고점 대비 눌림 반등) | 1.0% | 최대 6종목 | 트레일링(6 ATR)으로만 |
| 장기투자 | 장기 추세추종 (200일선) | 1.0% | 최대 6종목 | 추세 꺾일 때까지 |
| 스윙(중기) | 추세 눌림목 | 0.8% | 최대 5종목 | 오버나이트 허용 |
| 단타(당일) | 변동성 돌파 | 0.4% | 최대 3종목 | 15:15 전량 |
| 분봉 단타 | 시가 레인지 돌파 | 0.3% | 최대 2종목 | 15:10 전량 |

> **전략 비교는 이렇게 운용랩의 분리 계좌로 할 것.** 좋아 보이는 전략 여러 개를
> [설정]에서 한 계좌에 같이 켜면 서로 종목을 선점해 **둘 다 죽는다** —
> 실측: 조정 매수 단독 +114%가, 장투와 한 계좌에 섞으면 +3~5%로 무너졌다.
> 조정 매수의 수익은 소수 대박 종목에서 나오는데 다른 전략이 그 종목을
> 먼저 차지하면 대박 구간을 통째로 놓치기 때문이다. 엔진의 기본 활성
> 전략이 조정 매수 하나뿐인 이유다.

[편집]에서 전략 파라미터·자금관리·매매시간을 바꾸고, [복제]로 변형을 만들어 나란히 돌리면 된다.

**성과 비교표**가 보여주는 것 — 실제 경과시간, 초기자금, 현재평가, 실현손익, 평가손익,
총손익, 수익률, 예상 월/연 금액, 거래수, 승률, MDD. 자산곡선은 초기자금 대비 %로
정규화해 그리므로 자금이 달라도 비교된다.

> **예상 월/연 금액은 표본이 쌓이기 전까지 `—`로 표시된다.**
> 며칠치 수익률을 연으로 환산한 숫자는 통계가 아니라 착시다.
> 최소 5일 + 20거래가 쌓여야 표시한다.

### ⚡ 전략 자동 탐색 — 클릭 한 번

[종목] 또는 [운용랩] 탭의 **[⚡ 전략 자동 탐색]** 버튼.
종목을 주면(6자리 코드든 종목명이든) 전략·파라미터 조합을 훑어서 추천하고,
승인하면 프로필을 만들어 바로 가상운용을 시작한다.

**수익률 1등을 고르지 않는다.** 조합을 50개 돌려놓고 1등을 뽑으면 그중 하나는
순전히 운으로 좋아 보이기 때문이다. 그래서 관문을 먼저 통과해야 한다.

| 관문 | 기준 | 막으려는 것 |
|---|---|---|
| 거래 표본 | 30건 이상 | 우연히 몇 번 맞은 것 |
| 비용 후 수익 | > 0% | 비용에 지는 전략 |
| 손실 확률 | < 45% | 운 나쁘면 무너지는 것 |
| 연도별 일관성 | 절반 이상 수익 | 특정 해에만 벌었던 것 |
| 최대낙폭 | ≤ 35% | 실제로 못 버티는 것 |
| 종목 교체 | 종목 일부를 빼도 유지 | 그 종목이 우연히 맞았던 것 |

4단계로 진행한다 — ① 전략별 기본 성적 ② 상위 2개의 핵심 파라미터 훑기
③ 몬테카를로·연도별·민감도 검증 ④ 종목 일부를 빼고 재검증.
1~3분쯤 걸리고, **하나도 통과 못 하면 "추천할 만한 것이 없습니다"라고 말한다.**
억지로 1등을 고르는 것보다 그게 낫다.

### 기다리지 않고 결과 보기

**[⚡ 즉시 검증]** — 프로필 설정 그대로 과거 5년 데이터로 즉시 돌린다.
수익률·MDD·거래수에 몬테카를로 분포(90% 구간, 손실 확률)까지 한 번에 나온다.
설정을 바꿔가며 비교할 때는 이쪽이 실시간 운용보다 훨씬 빠르다.

실시간 랩은 "실제로 이 시각에 이 가격으로 주문이 나가는가"를 보는 용도고,
"얼마 버는가"는 즉시 검증으로 보는 게 맞다.

### 창을 꺼도 계속 돌리기

**[창 없이 실행]** 버튼을 누르면 별도 프로세스로 넘어간다. GUI를 닫아도 계속 돌고,
다시 켜면 그동안 쌓인 결과가 그대로 보인다.

```bash
python run.py --lab                  # 저장된 프로필 전부
python run.py --lab 장기투자 단타(당일)   # 지정한 것만
python run.py --lab-status           # 상태와 성과 확인
python run.py --lab-stop             # 정지 요청
```

exe도 같다 — `Clistock.exe --lab` 로 실행하면 창 없이 돈다.
GUI와 데몬은 DB로만 통신하므로 서로 껐다 켜도 상관없다.

### 창 닫기(X)는 종료가 아니다 — 트레이 최소화

GUI의 X 버튼은 앱을 끄지 않고 **트레이(작업표시줄 숨겨진 아이콘 ^)로 보낸다.**
엔진이나 가상운용이 도는 중에 창을 닫는 실수로 멈추지 않게 하기 위해서다.

- 트레이 아이콘 클릭 → **[열기]** 창 복원 / **[종료]** 진짜 종료
- `pystray` 가 설치되지 않은 환경에서는 예전처럼 X 로 바로 종료된다

### 무인 모의투자 러너 — `tools/auto_trade.py` (소스 실행 전용)

GUI 없이 모의투자 엔진만 돌리는 러너. exe 에는 들어 있지 않다.

```bash
python tools/auto_trade.py            # 오늘 16:40 까지 (작업 스케줄러용)
python tools/auto_trade.py --forever  # 끌 때까지 계속 (상시 실행용)
```

평일 아침 자동 시작은 작업 스케줄러에 등록한다:

```bash
schtasks /create /tn ClistockAutoTrade /sc weekly /d MON,TUE,WED,THU,FRI /st 08:50 /tr "pythonw <경로>\tools\auto_trade.py"
```

무인 실행이므로 안전장치가 들어 있다 — REAL 모드는 절대 자동 시작하지 않고,
모의 키가 죽어 PAPER 로 조용히 대체된 경우도 거부한다(`--paper` 로만 허용).
포트 잠금(47603)으로 이중 실행을 막고, GUI 는 이 포트로 러너를 감지해 KIS
호출 한도를 나눠 쓴다. **러너가 도는 동안 GUI [대시보드]의 엔진을 켜면
같은 계좌에 주문이 두 번 나간다** — GUI 는 조회용으로만 쓸 것.
기록은 `logs/trader.log` 에 남는다.

## [종목] 탭 — 검색과 목록

**검색**: 종목명이나 6자리 코드를 넣으면 국내 상장 **3,500여 종목**에서 찾는다.
결과를 더블클릭하면 관심종목에 들어간다.

> KIS OpenAPI에는 종목명 검색 API가 없다. 그래서 한국투자증권이 공개하는 종목 마스터
> 파일(`kospi_code.mst` / `kosdaq_code.mst`)을 받아 로컬 DB에 넣고 검색한다.
> 처음 한 번만 받으면 그다음부터는 오프라인에서도 즉시 검색된다.
> ([종목DB 갱신] 버튼으로 신규 상장 반영)

**하위 탭**

| 탭 | 내용 |
|---|---|
| 관심종목 | 자동매매 대상. 실시간 시세 (1회 호출로 30종목씩 조회) |
| 보유종목 | 계좌 잔고 |
| 최근조회 | 최근에 본 종목 |
| 국내순위 | 거래량 / 거래증가율 / 상승률 / 하락률 / 시가총액 (전체·코스피·코스닥) |
| 해외순위 | 상승률 / 하락률 / 거래량 / 거래대금 (나스닥·뉴욕·아멕스·도쿄·홍콩·상해·심천·베트남) |

어느 목록에서든 종목을 골라 관심종목에 넣을 수 있다.

> **"타사보유"는 넣지 못했다.** 한국투자증권 앱의 고유 기능이고 OpenAPI로는 공개되지
> 않는다. 대신 실제로 조회 가능한 순위들을 넣었다.
>
> **해외 종목은 조회 전용이다.** 이 프로그램의 자동매매는 국내주식만 다룬다.

## 구조

```
run.py                 단일 진입점
app/
  settings.py          .env(비밀) + config/settings.json(운영값)
  storage.py           SQLite - 캔들/신호/주문/체결/거래/자산곡선/종목마스터
  master.py            종목 검색 (마스터 파일 다운로드 + 로컬 검색)
  kis_client.py        KIS REST (토큰캐시·레이트리밋·hashkey·재시도)
  market.py            개장 여부 / 세션 판정 / 휴장일 캐시
  indicators.py        SMA·EMA·RSI·ATR (의존성 없는 순수 파이썬)
  strategies.py        전략 - "언제 사고 언제 파는가"만
  risk.py              자금관리 - "얼마나 사고 언제 멈추는가"
  broker.py            PaperBroker / KISBroker (동일 인터페이스)
  collector.py         일봉·분봉 수집
  backtest.py          백테스터 + 파라미터 그리드 탐색
  trader.py            실시간 엔진 루프
  profiles.py          투자 성향 프로필 (장투/스윙/단타 프리셋)
  lab.py               운용 랩 - 프로필별 독립 가상계좌 동시 운용 + 성과 집계
  notifier.py          텔레그램 알림
  analysis.py          견고성 분석 (민감도 / 연도별 / 몬테카를로)
  daemon.py            창 없이 도는 백그라운드 운용
  scanner.py           전략 자동 탐색 (관문 통과한 것만 추천)
  ai_advisor.py        Gemini - 리뷰/제안/거부권
  core.py              조립
  ui.py                단일 GUI
```

**전략과 리스크를 분리한 이유**: 섞어두면 백테스트와 실거래가 달라진다.
전략은 신호만 내고, 수량과 차단은 전부 `risk.py`가 정한다.
백테스터도 실거래와 **같은 Strategy 객체, 같은 사이징 공식**을 쓴다.

## 거래 모드

| 모드 | 시세 | 주문 | 용도 |
|---|---|---|---|
| `PAPER` | 실제 | 로컬 가상체결 | 키 없이 로직 확인 |
| `MOCK` | 실제 | 모의투자 계좌 | **여기서 데이터를 쌓는다** |
| `REAL` | 실제 | 실전 계좌 | 검증 완료 후 |

`REAL`은 [설정] 탭에서 **명시적으로 승인 체크**를 해야 열린다.
승인하지 않으면 `REAL`을 골라도 자동으로 `MOCK`으로 대체된다.

## 안전장치 (`risk.py`)

전략이 실패해도 계좌가 살아남게 하는 부분. 전략보다 중요하다.

| 항목 | 기본값 | 동작 |
|---|---|---|
| 1회 거래 최대손실 | 0.5% | 이 값에서 **매수 수량을 역산**한다 |
| 하루 최대손실 | 2% | 초과 시 당일 신규진입 전면 중단 |
| 누적 최대낙폭 | 10% | 초과 시 엔진 전체 정지 |
| 연속 손절 | 3회 | 초과 시 60분 쿨다운 |
| 재진입 금지 | 30분 | 손절 직후 재매수 차단 |
| 동시 보유 | 5종목 | |
| 종목당 비중 | 20% | |
| 최소 현금 보유 | 10% | 몰빵 방지 |
| 하루 주문 상한 | 40건 | 과매매 차단 |
| 업종 집중도 | 40% | 같은 업종 비중 초과 시 추가 매수 차단 |

수량 계산은 "얼마 살까"가 아니라 **"틀렸을 때 얼마 잃을까"에서 역산**한다.

```
위험금액 = 총자산 × 1회손실한도%
수량     = 위험금액 ÷ (진입가 − 손절가)
         (종목비중 / 가용현금 / 1회주문상한 중 가장 작은 값으로 다시 제한)
```

그 외 **중복 주문 잠금**(같은 종목 동시 주문 차단)과 **킬 스위치**(전량 청산 + 엔진 정지)가 있다.

## 백테스터가 거짓말하지 않게 만든 장치

낙관적인 백테스트는 손실보다 나쁘다. 틀린 확신을 주기 때문이다.

- 수수료 + 매도세 + 슬리피지를 **전부** 차감
- 같은 봉에서 손절·익절이 동시에 걸리면 **손절 우선** (최악 가정)
- 갭으로 손절가를 뛰어넘으면 **시가 체결** (손절가 체결 아님)
- 신호는 **직전 봉까지의 데이터로만** 생성 (미래참조 차단)
- 표본 부족·MDD 과다·수익 편중·PF 이상치에 **자동 경고**
- **비용 전 / 비용 후 수익률을 나란히** 표시 (수수료·세금·슬리피지 내역 포함)

무작위 워크 데이터로 돌리면 수수료만큼 손실이 난다. 즉, 가짜 수익이 나오지 않는다.

### 견고성 분석 — "이 설정이 진짜인가"

수익률 한 숫자는 거의 아무것도 말해주지 않는다. [백테스트] 탭의 세 버튼이 그걸 검증한다.

| 분석 | 답하는 질문 |
|---|---|
| **민감도** | 파라미터를 조금 바꾸면 결과가 얼마나 흔들리나? 최고점만 뾰족하면 과최적화다 |
| **연도별 성과** | 특정 해에만 벌었나, 꾸준한가? (각 해마다 워밍업 구간을 앞에서 따로 읽어 보정한다) |
| **몬테카를로** | 같은 거래를 다시 뽑았다면? 손실로 끝날 확률과 최악 낙폭의 분포 |

몬테카를로는 순서만 섞지 않고 **복원추출로 다시 뽑아 복리로 굴린다.**
손익을 절대금액으로 더하면 순서를 바꿔도 합계가 같아서 분포가 생기지 않기 때문이다.

실제 결과 예 (장기 추세추종, 166거래):

```
실제 백테스트   +59.6%
분포 중앙값     +49.4%
90% 구간        -18.3% ~ +234.9%
손실 확률       15%
나쁜 경우 MDD   36.1%
```

백테스트 +59.6%는 **일어날 수 있었던 여러 결과 중 하나**일 뿐이고,
같은 전략으로 15% 확률로 손실이 났을 수도 있었다는 뜻이다.

### 실제로 나온 결과 (2020-07 ~ 2026-10, 18종목)

v1.1.1에서 백테스터의 "당일 종가 청산이 다음날로 밀리던" 버그를 고친 뒤
전부 다시 돌린 결과다. 이전 표의 수치는 그 버그 때문에 낙관적이었다.

**바꾸기 전 (이전 기본값):**

| 전략 | 비용 전 | 비용 후 | 거래수 | MDD |
|---|---|---|---|---|
| 변동성 돌파 (단타) | -24.6% | **-63.3%** | 1,718 | 63.4% |
| 추세 눌림목 (스윙) | +12.3% | **-6.1%** | 461 | 29.9% |
| 장기 추세추종 (장투) | -13.3% | **-29.1%** | 400 | 48.3% |
| 조정 매수 | +32.1% | **+22.9%** | 219 | 23.2% |

여기서 **"거래를 줄이고 보유를 늘리는"** 방향으로 파라미터를 다시 잡은 것이
지금의 기본값이다. 그리드 1등을 뽑은 게 아니라, 몬테카를로·연도별·종목 교체
검증을 통과하고 **이웃 값에서도 결과가 유지되는 방향만** 채택했다.

**바꾼 후 (현재 기본값):**

| 전략 | 바뀐 것 | 비용 후 | 거래수 | MDD | 손실확률 |
|---|---|---|---|---|---|
| 조정 매수 | 트레일링 3.5 → 6.0 ATR | **+117.9%** | 180 | 32.4% | 11% |
| 장기 추세추종 | 트레일링 2.5 → 4.5, 모멘텀 문턱 5 → 15% | **+59.6%** | 166 | 30.1% | 15% |
| 추세 눌림목 | 보유 15 → 30봉, 목표 2R → 3R, 트레일링 2.5 → 3.5 | **+8.0%** | 422 | 31.1% | 39% |
| 변동성 돌파 | (변경 없음 — 비용 구조상 구제 불가) | -63.3% | 1,718 | 63.4% | — |

패턴은 하나다. **거래비용(왕복 0.38% = 수수료 0.03 + 매도세 0.15 + 슬리피지 0.20)이
이 시스템의 최대 적이고, 이기는 쪽은 전부 보유가 긴 전략이다.** 1,718거래한 단타는
38.6%p를 비용으로 냈다. 좁은 트레일링 스톱은 추세 중간의 흔들림에 털려서
"크게 먹는 구간"을 끊어먹는다 — 트레일링을 넓힌 게 세 전략 모두에서 가장 컸다.

### 홀드아웃 검증 — 이 기본값이 그 18종목에만 맞춘 게 아닌가?

튜닝에 **전혀 쓰지 않은** 별도 20종목(신한지주·한전·LG생활건강·엔씨소프트·
넷마블·알테오젠 등 승자·패자 혼합)으로 같은 기간을 다시 돌렸다.

| 전략 | 학습 18종목 | 검증 20종목 | 슬리피지 2배 (검증) |
|---|---|---|---|
| 조정 매수 | +112% (MDD 32%) | **+203%** (MDD 35%) | +199% |
| 장기 추세추종 | +61% (MDD 30%) | **+44%** (MDD 19%) | +40% |
| 추세 눌림목 | +8% (MDD 29%) | **+24%** (MDD 20%) | +7.6% |

세 전략 모두 처음 보는 종목에서 재현됐고, 슬리피지를 2배로 올려도 살아남았다
(거래 많은 눌림목만 크게 깎인다 — 알려진 약점 그대로).

검증에서도 남는 특성 두 가지:

- **수익은 소수 종목에 쏠린다** (검증 유니버스에서 조정 매수 수익의 76%가
  삼성전기). 결함이 아니라 성격이다 — 승률 16~26%로 소수의 대박이 다수의
  소손실을 갚는 구조라서, 관심종목을 15개 이상 넉넉히 둬야 "크게 회복하는 놈"이
  그물에 걸린다.
- **2022년 같은 약세장에서는 전부 마이너스였다** (-6 ~ -16%). 롱 온리 추세
  전략의 구조적 한계다.

두 가지는 알고 있어야 한다.

- **같은 기간 18종목을 그냥 사서 들고 있었으면 +428%였다.** 다만 이 유니버스에는
  하이닉스·에코프로처럼 사후에 확인된 대박 종목이 들어 있어 벤치마크가 과하게 높다.
  전략의 가치는 수익률 경쟁이 아니라 MDD(65% → 30%대)와 손실확률 관리에 있다.
- 기존에 쓰던 사람은 설정이 config 에 저장돼 있어 **새 기본값이 자동 반영되지
  않는다.** [운용랩] 의 프리셋 초기화를 누르거나 [편집]에서 직접 바꿔야 한다.

## 모의투자 서버가 응답하지 않을 때

한국투자증권 **모의투자 도메인은 종종 멈춘다.** TCP는 연결되는데 HTTP 응답이 오지 않는다.
설정이나 키 문제가 아니다. 이 경우 앱은 이렇게 버틴다.

- 잔고 조회는 **9초 안에 끊고** 마지막으로 받은 값을 계속 보여준다 (화면이 0원이 되지 않음)
- 연속 실패하면 재시도 간격을 **15 → 30 → 60초**로 늘려 서버를 더 괴롭히지 않는다
- 대시보드에 `계좌 갱신 실패 - HH:MM:SS 기준 값 표시 중` 이라고 표시된다
- 엔진은 죽지 않고 그 회차만 건너뛴다

**시세는 실전 도메인을 쓰므로 이 상황에서도 데이터 수집·백테스트·종목 검색은 정상 동작한다.**
모의 주문만 잠시 멈출 뿐이다. [설정] → PAPER 모드로 바꾸면 검증은 계속할 수 있다.

**휴장일 판정도 API 없이 버틴다** — 휴장일 API(실전 도메인 전용)를 못 쓰는 상황
(모의 키만 있음, 서버 장애)에서는 내장 휴장일 표(2025~2027)로 폴백한다.
2025~2026년분은 실제 거래일 데이터로 검증했고, **2027년분은 음력 환산 추정이
섞여 있어 2026년 말 KRX 공고가 나오면 갱신해야 한다** (`app/market.py`의
`KNOWN_HOLIDAYS`). 임시공휴일·임시휴장은 API만 알 수 있으므로 폴백 결과는
DB에 캐시하지 않고, API가 살아나면 그쪽이 우선한다.

## 배포와 자동 업데이트

**저장소에는 소스만, 릴리즈에는 실행 파일만** 올라간다.
`.gitignore` 가 `.env`·앱키·DB·로그·exe 를 전부 막고 있다.

### 처음 한 번 (GitHub 저장소 연결)

```bash
git remote add origin https://github.com/<owner>/<repo>.git
git branch -M main
git push -u origin main
```

### 새 버전 내보내기

```bash
python release.py 1.0.1        # 버전 올리고 커밋 + 태그
git push && git push origin v1.0.1
```

태그를 밀면 `.github/workflows/release.yml` 이 windows-latest 에서 exe를 빌드해
릴리즈에 붙인다. 태그와 `app/version.py` 가 다르면 빌드가 중단되므로 버전이 어긋날 일이 없다.

직접 빌드해서 올리려면 (`gh` CLI 필요):

```bash
python release.py 1.0.1 --local
```

### 사용자 쪽 자동 업데이트

[설정] 탭 → **자동 업데이트** 에 저장소를 `owner/repo` 형식으로 넣으면 된다.

- 시작할 때 최신 릴리즈를 확인하고, 새 버전이 있으면 알려준다
- 승인하면 내려받아 교체하고 새 버전으로 다시 실행된다
- **확인 없이 자동 설치** 를 켜면 물어보지 않고 바로 교체한다 (기본 꺼짐)

교체 방식 — 실행 중인 exe는 자기 자신을 덮어쓸 수 없으므로, 프로세스 종료를
기다렸다 파일을 바꾸고 재실행하는 스크립트를 띄우고 앱은 종료한다.
원본은 `.exe.bak` 으로 남기고, 교체에 실패하면 되돌린다.

안전장치: 설정된 저장소에서만, HTTPS로만, 허용된 GitHub 호스트에서만 받고,
크기를 검증한 뒤에 교체한다.

> 소스로 실행 중일 때는 자동 교체를 하지 않는다 (`git pull` 을 쓰라고 안내만 한다).

## 주의

- 이 프로그램은 **도구**이지 투자 조언이 아니다. 수익을 보장하지 않는다.
- `.env`와 `실전 앱 키.txt`에는 계좌 접근 권한이 들어 있다. 절대 공유하지 말 것.
  (`.gitignore`에 등록해 뒀다)
- 실전 전환 전 최소한 이 정도는 확인할 것:
  - 백테스트 거래 **30건 이상**, 여러 종목·여러 기간에서 일관된 결과
  - 모의투자 **수십 거래** 이상, 백테스트와 방향이 어긋나지 않는지
  - MDD가 본인이 **실제로 견딜 수 있는** 수준인지
- 실전은 극소액부터. 백테스트가 좋아 보인다는 이유만으로 금액을 키우지 말 것.
